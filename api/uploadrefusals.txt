# Graphite Meter upload refusal pin, shared by the Rust workspace and the browser client.
#
# Format (one refusal per non-comment, non-blank line):
#   <name> | <message> | <http status>
#
#   name    = the key every implementation uses for the refusal
#   message = the exact text the server sends, byte for byte
#   status  = the HTTP status the message is sent with. It applies to the
#             request/response routes only; over a WebTransport stream there is
#             no status line, so the message travels alone (see below).
#
# These strings are a wire contract, not internal diagnostics. A refused upload
# reports its reason twice over, in two shapes that must stay in step:
#   HTTP: /upload and /upload/progress send the message as the response body.
#   WT:   the progress stream carries it as {"type":"error","code":"...",
#          "message":"..."}. A stream has no status line, so `code` gives the
#          client the recovery disposition without inferring it from prose.
#   HTTP: the same code is present in X-Graphite-Upload-Refusal.
# Every refusal test loads THIS file as its fixture:
#   Rust: rust/proto/tests/codes.rs (proto::refusal, both the text and the status)
#   TS:   client/src/engine/lanes/endings.test.ts (the fatal records the progress feed surfaces)
#
# The failure reason each refusal ends a stage with is pinned in uploadrefusalreasons.txt.
#
# An accepted upload is not a refusal and carries no message, so it has no row.

invalid | unknown upload id | 400
globalFull | upload capacity exhausted | 503
clientFull | client upload capacity exhausted | 429
ownerMismatch | upload id belongs to another client | 403
idle | idle | 408
revoked | authentication required | 403
